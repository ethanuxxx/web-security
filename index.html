    步驟 1／6

    瀏覽器組出 request

    瀏覽器組出 GET /profile，並自動附上 Cookie。

    可能出問題：伺服器之後靠 Cookie 認人。

    對應章節

    • 第 1 章 Web 基礎
      • 1.3 HTTP, Cookies, and Burp Suite

    步驟 2／6

    CDN 先找有沒有現成的副本

    CDN（網站前的快取代理）用 cache key 找副本，沒有（miss）才往後送。

    可能出問題：cache key 的組成，決定誰會拿到同一份回應。

    對應章節

    • 第 9 章 Proxy 與快取
      • 9.2 Web Cache Poisoning

    步驟 3／6

    轉給 Web application，先認出你是誰

    Web application 拿 Cookie 查 session，認出你是 alice。

    可能出問題：Cookie 被偷或驗證有漏洞，你就會被當成別人。

    對應章節

    • 第 3 章 登入與權限
      • 3.1 Authentication

    步驟 4／6

    拆成子 request，向後端要資料

    拆成兩個子 request：用 SQL 查 Database，並讀出 File system 的頭像。

    可能出問題：子 request 夾著使用者給的值（id、檔名），是注入與路徑穿越的入口。

    對應章節

    • 第 2 章 使用者輸入
      • 2.1 Path Traversal
      • 2.3 SQL Injection

    步驟 5／6

    組成 HTML，沿原路回去

    結果組成 HTML，原路經過 CDN；CDN 看回應標頭決定能不能存副本。

    可能出問題：含個人資料的頁面被存進共用快取，下一個人就看得到。

    對應章節

    • 第 9 章 Proxy 與快取
      • 9.3 Web Cache Deception

    步驟 6／6

    瀏覽器把 HTML 畫成頁面

    瀏覽器解析 HTML，一層層長出頁面。

    可能出問題：瀏覽器照 HTML 執行內容，不可信的內容混進來就是 XSS。

    對應章節

    • 第 2 章 使用者輸入
      • 2.6 Cross-Site Scripting
