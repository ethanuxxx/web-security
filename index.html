    步驟 1／6

    瀏覽器組出 request

    你在網址列開啟 /profile，瀏覽器組出一筆 request，並自動附上這個網站的 Cookie。

    這裡的信任邊界／可能出問題的地方：Cookie 是瀏覽器替你附上的，伺服器之後靠它認人。

    對應章節

    • 第 1 章 Web 與 HTTP
      • 1.2 HTTP Requests and Sessions

    步驟 2／6

    CDN 先找有沒有現成的副本

    request 先到 CDN（放在網站前面的快取代理）；CDN 拆開看 cache key，發現沒有存過這一頁（miss），所以才繼續往後送。

    這裡的信任邊界／可能出問題的地方：cache key 用什麼組成，決定兩個人會不會拿到同一份回應。

    對應章節

    • 第 10 章 Proxy、Cache 與後端看到的不一樣
      • 10.1 Host Headers and Web Caches

    步驟 3／6

    轉給 Web application，先認出你是誰

    CDN 把 request 轉給 Web application；程式先拿 Cookie 去查 session，確認是哪位使用者。

    這裡的信任邊界／可能出問題的地方：這一步決定「你能看哪些資料」；Cookie 被偷或驗證有漏洞時，就會被當成別人。

    對應章節

    • 第 4 章 網站如何知道你是誰、允許你做什麼
      • 4.1 Authentication

    步驟 4／6

    拆成子 request，向後端要資料

    Web application 不自己存資料：它把需求拆成兩個子 request，向 Database 下 SQL 查詢，並向 File system 讀出頭像檔。

    這裡的信任邊界／可能出問題的地方：子 request 裡常夾著使用者給的值（這裡的 id 與檔名），這就是注入與路徑穿越類漏洞的入口。

    對應章節

    • 第 2 章 伺服器如何處理使用者輸入
      • 2.1 Path Traversal
      • 2.3 SQL Injection Basics

    步驟 5／6

    組成 HTML，沿原路回去

    兩個結果回到 Web application，被組成一份 HTML 回應，原路經過 CDN；CDN 會看回應標頭，決定能不能存一份副本。

    這裡的信任邊界／可能出問題的地方：含個人資料的頁面若被誤存進共用快取，下一個人就可能看到別人的內容。

    對應章節

    • 第 10 章 Proxy、Cache 與後端看到的不一樣
      • 10.1 Host Headers and Web Caches

    步驟 6／6

    瀏覽器把 HTML 畫成頁面

    回應回到瀏覽器；瀏覽器解析 HTML，一層層長出你看到的頁面。

    這裡的信任邊界／可能出問題的地方：瀏覽器會照 HTML 執行裡面的內容，不可信的內容混進 HTML，就是 XSS 的入口。

    對應章節

    • 第 3 章 伺服器的輸出如何在瀏覽器中變成程式
      • 3.1 Cross-Site Scripting Basics
